# py_to_notebook

Скрипт собирает все `.py` файлы из выбранной папки (включая вложенные) в один Jupyter-блокнот `.ipynb`. Каждый файл попадает в блокнот двумя ячейками: заголовок с путём и датой изменения и ячейка с кодом.

Удобно, когда нужно быстро собрать весь проект в один документ: для сдачи работы, ревью, печати или загрузки в нейросеть.

## Возможности

- Рекурсивный поиск `.py` файлов в выбранной папке
- Выбор папки и места сохранения через окно `tkinter`. Если `tkinter` недоступен, скрипт переходит на ввод путей в консоли
- Четыре критерия сортировки: путь/имя, дата изменения, дата создания, размер файла
- Сортировка по возрастанию или по убыванию
- Автоматический пропуск служебных папок: `.git`, `.venv`, `venv`, `__pycache__`, `node_modules`, `.idea`
- Сам скрипт и выходной `.ipynb` в блокнот не попадают
- Чтение файлов в `utf-8-sig`, а при ошибке в `cp1251`. Файлы, которые не удалось прочитать, пропускаются с сообщением в консоли

## Требования

- Python 3.6 или новее
- Только стандартная библиотека, ничего устанавливать не нужно
- `tkinter` нужен для графических диалогов, но не обязателен. В Linux он может ставиться отдельно (например, пакет `python3-tk`)

## Запуск

```bash
python py_to_notebook.py
```

Дальше скрипт задаёт вопросы по шагам:

1. **Папка с `.py` файлами.** Открывается диалог выбора папки, либо нужно ввести путь вручную.
2. **Критерий сортировки (1-4).** По умолчанию 1.

   | Номер | Критерий |
   |-------|----------|
   | 1 | путь/имя (по умолчанию) |
   | 2 | дата изменения |
   | 3 | дата создания |
   | 4 | размер файла |

3. **Направление сортировки (1-2).** 1 по возрастанию (по умолчанию), 2 по убыванию.
4. **Куда сохранить блокнот.** Предлагается `notebook.ipynb` в выбранной папке.

Пример вывода:

```
Готово! Добавлено файлов: 12, пропущено: 0
Сортировка: дата изменения (по убыванию ↓)
Блокнот сохранён по пути: C:\projects\my_app\notebook.ipynb
```

Если на вопросе ввести что-то другое или оставить поле пустым, применяется значение по умолчанию.

## Структура результата

Для каждого найденного файла в блокнот добавляются две ячейки:

1. **Markdown-ячейка** с заголовком: `## относительный/путь/файл.py (изменён: ГГГГ-ММ-ДД ЧЧ:ММ)`
2. **Code-ячейка** с полным содержимым файла

Ячейки пишутся с `execution_count: null` и пустым выводом. Код не выполняется, блокнот содержит только исходники. Ядро по умолчанию: Python 3.

## Нюансы

- **Дата создания.** В Windows и macOS берётся настоящая дата создания файла. В Linux такой даты у файла часто нет, и скрипт использует `st_ctime` (время последнего изменения метаданных). Для критерия 3 в Linux результат может отличаться от ожидаемого.
- **Пропуск самого себя.** Скрипт исключается из списка по пути, с которым он был запущен. Если запускать его копию из другого места, копия может попасть в блокнот.
- **Кодировки.** Поддерживаются только `utf-8-sig` (включая обычный UTF-8) и `cp1251`. Файлы в других кодировках будут пропущены.
- **Другие типы файлов.** Скрипт обрабатывает только `.py`. Файлы `.ipynb`, `.txt`, `.json` и остальные игнорируются.
- **Размер блокнота.** Блокнот содержит весь код целиком, поэтому на больших проектах файл может получиться тяжёлым.
